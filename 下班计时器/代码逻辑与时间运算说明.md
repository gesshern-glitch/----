# 下班计时器 — 代码逻辑与时间运算说明

## 一、技术架构

| 层 | 文件 | 职责 |
|---|---|---|
| 主进程 (Node.js) | `main.js` | 创建 Electron 窗口（330×525，无边框透明毛玻璃），处理窗口最小化/关闭 IPC；点 ✕ / 最小化收进系统托盘（双击托盘图标恢复，右键菜单可「检查更新」或「退出」），打包后启用自动更新 |
| 更新文案处理 | `updateNotes.js` | 把 GitHub Release 正文（Markdown）洗成弹窗里能看的几行：去 `#`/`**`/反引号/链接/分隔线，列表符号统一成 `·`，最多 12 行。纯函数，可用 node 直接跑断言 |
| 预加载脚本 | `preload.js` | 通过 `contextBridge` 安全暴露 `window.winControl`（minimize / close）与 `window.store`（load / save / saveSync / dataPath / openFolder）给渲染进程 |
| 渲染进程 | `renderer.js` | **全部业务逻辑**：计时、打卡、工时计算、补贴、出勤统计、日历 |
| 页面 & 样式 | `index.html` / `styles.css` | UI 结构与毛玻璃视觉风格 |

数据持久化：记录存在用户机器上的 `文档/下班计时器/出勤记录.json`（同时自动生成一份同名 CSV），无需后端。

## 二、核心常量

| 常量 | 值 | 含义 |
|---|---|---|
| `TOTAL_MIN` | 555 分钟（9h15m） | 上班到推荐下班的总时长 = 标准工时 + 午休 |
| `LUNCH_MIN` | 90 分钟 | 午休时长 |
| `BASE_MIN` | 465 分钟（7h45m） | 每日标准出勤工时 |
| 午休固定时段 | 12:30 — 14:00 | 只有落在该时段内的在岗时间才被扣除 |

## 三、时间运算详解

### 3.1 推荐下班时间

```
推荐下班时间 = 上班时间 + 9小时15分钟
```

例：09:00 上班 → 推荐下班 18:15。

### 3.2 午休扣除（固定时段法）

午休不是简单减 1.5 小时，而是计算**在岗区间与 12:30-14:00 的实际重叠**：

```
午休重叠 = max(0, min(下班时刻, 14:00) - max(上班时刻, 12:30))
```

几种情况：

| 上班 → 下班 | 在岗时长 | 午休重叠 | 实际工时 |
|---|---|---|---|
| 09:00 → 18:15 | 9h15m | 90 分钟 | 7h45m |
| 09:00 → 12:00 | 3h | 0 分钟 | 3h |
| 13:00 → 18:00 | 5h | 60 分钟 | 4h |
| 12:00 → 15:00 | 3h | 90 分钟（完整覆盖） | 1.5h |

### 3.3 工时 & 加班

```
实际工时 = 在岗时长 - 午休重叠（最多扣 90 分钟）
加班时长 = max(0, 实际工时 - 7小时45分钟)
```

### 3.4 补贴档位

基于**扣除午休后的实际工时**：

| 实际工时 | 补贴金额 |
|---|---|
| > 9 小时 | 30 元 |
| > 10 小时 | 60 元 |
| > 11.5 小时 | 100 元 |

从高到低匹配，取最高档。

### 3.5 补贴目标时刻推算

当已过推荐下班时间，界面切换为倒计时下一个补贴档位。目标时刻的计算需要**反向推算**——因为加班期间也会经过午休时段，所以采用迭代逼近（3 次迭代足够收敛）：

```
目标时刻 = 上班时刻 + 档位工时 + 期间覆盖的午休时间
```

### 3.6 打卡结算

- **手动打卡**：点击「下班打卡」时记录当前时间，同时固化 `workMin`、`overtimeMin`、`subsidy` 快照到数据文件，后续不再变动。
- **自动结算**：应用启动时 / 每分钟刷新时，扫描所有过往日期——未打卡的自动以 **23:59** 作为下班时间结算并固化。
- **日历补录**：点已过去的无记录日期，填入上下班时间→按 `calcDay()` 走与主界面完全相同的算法（含 12:30-14:00 午休冻结）算出工时/加班/补贴，写入记录并标记 `source: "manual"`。
- **历史保留**：所有月份的记录**永久保留**；「本月统计」里的出勤天数/出勤率只算当前月，累计补贴与日均加班跨月累计；出勤日历与记录列表支持月度翻页回看。
- **月度翻页**：日历标题两侧 ‹ › 逐月切换（向左任意回看，向右不超过当月）；记录列表标题跟随浏览月份，跨入新月份时自动回到当月。

## 四、出勤统计逻辑

### 4.1 工作日判定

按优先级：
1. 在 `EXTRA_WORKDAYS` 集合中 → **工作日**（调休补班）
2. 在 `HOLIDAYS` 集合中 → **休息日**（法定节假日）
3. 按周一到周五判断 → 工作日；周六日 → 休息日

内置 **2026 年**全年放假调休安排（国办发明电〔2025〕7号）。

### 4.2 出勤天数 & 出勤率

两个卡片共用“有记录即出勤”的定义，但**分母口径不同**：

| 卡片 | 分子 | 分母 |
|---|---|---|
| 出勤天数（已勤 / 本月按日历应勤） | 本月有打卡记录的天数 | 本月**按日历本该出勤的工作日总数**（含调休补班，不含周末与法定节假日，**未来的工作日也计进去**） |
| 当月出勤率（按已过完的工作日） | 其中**已过完**且来打卡的天数 | 本月**已过完**的工作日天数（`d < 今天`，今天不计，避免刚打开软件就被扣分） |

```
出勤率 = 已过完且有记录的工作日天数 / 已过完的工作日天数 × 100%
```

- 没打开软件也没补录的日子：日历上显示为**空白**（不涂灰），但仍计入分母，因此自然拉低出勤率
- 休息日（周末/节假日）若填了记录：**只算进「出勤天数」的分子**，不进出勤率的分子分母 —— 鼠标悬停在「出勤天数」卡片上会提示“其中休息日还来上班 N 天（不计入出勤率）”

> 出勤率 > 90% 显示红色，≤ 90% 显示蓝色。已取消“上/下半天、手动缺勤”标记体系，出勤一律用“填上下班时间”表达。

### 4.3 日均加班

```
日均加班 = 全部月份累计加班分钟数 / 全部月份有记录天数
```

### 4.4 累计补贴

**跨月累计**：数据文件里所有月份记录的补贴之和（含当天实时补贴）。因为记录永久保留，翻页回看历史月份不会丢统计，但「出勤天数」与「当月出勤率」仍为**当月口径**。

## 六、闪烁提醒

到达推荐下班时间后，整个卡片以白色高亮动画闪烁（0.9s 周期），顶部显示「到点啦！可以下班了」横幅。用户可点击「停止闪烁」手动关闭，本次运行内不会再次触发。

## 七、数据存储结构

数据不再存在软件内部，而是落在用户能直接打开的文件里：

| 文件 | 位置 | 作用 |
|---|---|---|
| `出勤记录.json` | `文档/下班计时器/`（Mac：`~/Documents/下班计时器/`） | 程序读写的唯一数据源 |
| `出勤记录.csv` | 同上 | 每次保存自动重写，列：日期,上班时间,下班时间,工时(小时),加班(小时),补贴(元),记录来源（带 BOM，Excel 直接打开不乱码） |

```json
{
  "version": 1,
  "updatedAt": "2026-10-20T02:15:00.000Z",
  "records": {
    "2026-10-20": { "start": "09:30", "end": null },
    "2026-09-10": { "start": "09:00", "end": "18:30", "workMin": 480, "overtimeMin": 15, "subsidy": 0, "source": "manual" }
  }
}
```

- 渲染进程启动时 `await loadData()` 把文件读入内存对象 `DB.records`，`getRecord/setRecord/delRecord` 均读写该内存对象；写操作后 300ms 防抖落盘，窗口关闭前额外同步写一次。
- 当日未打卡时 `end` 为 `null`，无固化字段；打卡/自动结算/补录后写入 `workMin`、`overtimeMin`、`subsidy` 快照。
- `source: "manual"` 表示日历补录；无此字段表示软件当场打卡或过期自动结算。
- **旧版本迁移**：若数据文件不存在而旧版 localStorage（`workday-YYYY-MM-DD`）有记录，首次启动自动迁移写入文件；旧的手动标记（`attendance-overrides`）已废弃，不再迁移。

## 八、发布与自动更新

**仅把代码 `git push` 到 GitHub 不会让已安装的软件更新**；用户端读的是 GitHub **Release 附件里的 `latest.yml`**，所以必须把打包产物发布成 Release。

### 8.1 客户端行为（`main.js`）

| 时机 | 做的事 |
|---|---|
| 启动后 5 秒 / 每 30 分钟 | `autoUpdater.checkForUpdates()`（仅 `app.isPackaged` 时启用） |
| 发现新版本 | 弹窗：新版本号 + **Release 正文清洗后的更新日志** + `[现在下载] [以后再说]`（`autoDownload = false`，不征得同意就不下载几十兆） |
| 下载完成 | 弹窗 `[立即更新] [稍后再说]`；选立即更新走 `quitAndInstall(true, true)`（静默安装、装完自动重拉） |
| 选「稍后再说」 | `autoInstallOnAppQuit` 默认为 true，下次退出软件时自动装 |
| 托盘菜单「检查更新」 | 手动触发；已最新时提示“已经是最新版本”，失败时提示“暂时连不上更新服务器” |

### 8.2 发布流程

```powershell
npm version 1.3.0 --no-git-tag-version      # 1. 抬版本号（不改号等于没更新）
git add -A; git commit -m "v1.3.0: …"; git tag v1.3.0
git push origin main --tags                  # 2. 推代码与 tag
$env:GH_TOKEN = "…"; npm run release        # 3. 打包 + 自动建 Release + 上传附件
npm run verify                                # 4. 自检：附件齐不齐、名字与大小对不对得上
```

打包完但还没上传时，可先做一轮不联网的自检（校 `latest.yml` 里的文件名/大小/sha512 与 `release/` 里的实际字节是否一致，以及 blockmap 在不在）：

```powershell
npm run dist
npm run verify:local
```

不想用 token 就把第 3 步换成：`npm run dist` → 在 GitHub 网页建 tag 为 `v1.3.0` 的 Release → 上传 `release/` 里的 `off-work-timer-setup-1.3.0.exe`、`.exe.blockmap`、`latest.yml` 三个文件 → 描述里贴更新日志 → Publish。`npm run verify` 会拉 GitHub 上的 Release 做同样核对，并预览用户看到的更新日志文案。

> 安装包文件名固定用 ASCII（`artifactName: off-work-timer-setup-${version}.${ext}`）：中文名在 Release 下载 URL 上容易出编码问题，而且一旦与 `latest.yml` 里记的名字不一致，用户点更新会直接 404。`scripts/verify-release.js` 就是专门查这一类错的。
